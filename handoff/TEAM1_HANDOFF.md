# 팀원1 인계 — 무엇을 완성하고 무엇을 돌려주면 되는가

기준일: 2026-11-08. 이 문서는 현재 프로젝트 맥락과 역할을 정리한 작업 인계서다. 교수자의 별도 특허분석 의무 가이드가 아니다.

## 프로젝트의 목적

삼성물산이 AI 데이터센터 분야에서 추진할 신사업과 기술확보 전략을 제안한다. 과제의 흐름은 산업·시장·기술 전망 → 기업 현황 → 신사업 기회 → 대안 평가 → 실행전략이다. 특허 파트는 **DLC(콜드플레이트 중심 직접액체냉각)와 액침냉각을 어떻게 비교하고, 삼성물산이 어떤 기술을 어떤 방식으로 확보할지** 판단하는 근거를 제공한다. 특허 수가 많은 기술을 자동 선택하는 과제가 아니다.

중간발표에서는 삼성물산의 관련 기술·특허 존재를 확인하는 사례 소개에 집중했다. 기말에는 미국 정량분석과 국내 자사 분석을 연결하려고 한다. 결과 담당자가 최종 전략을 작성하려면 비교 가능한 기술별 결과와 해석 범위가 필요하다.

|---|---|---|

- 삼성물산·데이터빈 공동등록: **10-2552810**(유로 분배), **10-2815358**(상태·온도 기반 펌프 제어).

- IPC 검색 4건 중 기존 3건 회수, 추가 현대건설 직류 전력량계는 제외. 넓은 시설 탐색 82건은 보조 검토이며 별도 완성 코호트가 아님.

## 팀원1 작업 순서

### 1. 데이터와 검색 기준 확정

기존 작업이 있으면 먼저 원자료·검색식·검색일·집계 단위를 확인한다. 계획 범위는 미국 출원 2000–2024년이다. 실제 검색 서비스와 접근 가능한 필드에 맞추어 DLC/액침 정의, 포함·제외 기준, 중복 처리 방식을 문서화한다. 단어만 일치하는 배터리·ESS·일반 HVAC 등은 서버 냉각 여부로 구별한다. 칩 분사냉각처럼 분류 경계에 있는 기술은 별도 표시한다.

원본 export를 보존하고 정제 데이터는 따로 만든다. 공개·등록 문서와 continuation, 동일 패밀리를 어떻게 다뤘는지 명시한다. 연도별 추이를 출원번호로 집계한다면 전체 분석에서 그 단위를 일관되게 사용하고, 패밀리 기준 결과와 혼용하지 않는다. 두 기술에 동시에 해당하는 건은 중복 태그 또는 우선 분류 규칙을 정한다. 출원인 정규화는 원래 명칭과 통합 명칭을 모두 남긴다.

### 2. 기본 정량분석

| 분석 | 필요한 입력 | 반환할 결과 | 해석 주의 |
|---|---|---|---|
| 연도별 출원 추이 | 기술 분류, 출원일, 고유 ID | 기술별 연도·건수 표와 그래프 | 공개 지연, 불완전 최근연도, 검색일 명시 |
| 성장률 | 동일 기준 기간별 건수 | 최근 5년 정의·계산식·원수치 | 기준연도 0 또는 작은 표본에서 과장 금지 |
| CPC 구성 변화 | CPC 코드, 연도, 고유 ID | 코드 정의와 기간별 건수·구성비 | 다중 코드 중복집계인지 분할배분인지 명시 |
| 출원인 순위·HHI | 정규화 출원인, 기업별 건수 | 순위표, 점유율, HHI 계산표 | 특허 집중도이지 매출 시장점유율이 아님 |
| 신규 출원인 | 해당 검색범위 내 최초 출원연도 | 연도별 신규 수와 정의 | 검색기간 이전 이력이 누락될 수 있음 |
| 건물·설비 연계 | 명세서/청구항·분류 기준 | 분모·분자·비중·추이·주요 기업 유형 | 배관 등의 일반 단어만으로 연계 판정하지 않기 |

HHI를 0–1 척도로 계산하면 `Σ(기업별 특허 비중²)`이며 0–10,000 척도와 구별한다. 공동출원을 완전계수 또는 분할계수 중 무엇으로 처리할지 정하고, 비중의 합과 분모를 확인한다. 서로 다른 계수 방식의 HHI를 직접 비교하지 않는다.

### 3. 핵심특허 목록을 먼저 전달 — 팀원2의 직접 의존성

기술별로 최대 10건을 목표로 하되, 표본이 부족하면 실제 가능한 건수와 이유를 적는다. ‘핵심’은 단순히 검색 상위에 노출됐다는 뜻이 아니다. 관련성, 인용 또는 중요 출원인, 대표 청구항·기술 범위 등 선정 규칙과 각 특허의 선정 이유를 남긴다. 피인용을 쓰면 출원/공개 연령과 조회일을 함께 다루고 최근 특허를 기계적으로 불리하게 평가하지 않는다.

**아래 컬럼을 가진 CSV/Excel 또는 동등한 표를 반환:**

| 필수 필드 | 내용 |
|---|---|
| `technology` / `rank` | DLC 또는 Immersion, 선정 순서 |
| `application_number` | 미국 출원번호 |
| `publication_number` / `grant_number` | 실제 검토할 공개·등록 문헌번호; 없으면 공란 이유 |
| `family_id` / `dedup_rule` | 패밀리 식별 및 중복 처리 기준 |
| `title` / `applicant_raw` / `applicant_normalized` | 원명칭과 정규화 명칭 |
| `filing_date` / `priority_date` | 연도 기준 혼용 방지 |
| `legal_status` / `status_checked_at` | 확인된 범위의 상태·확인일 |
| `source_url` / `claims_url` | 서지와 실제 청구항 원문 링크 |
| `selection_reason` / `selection_metric` | 각 건의 선정 이유·선정에 사용한 실제 지표 |
| `building_link` / `building_link_reason` | 건물 연계 여부와 근거 문단/청구항 |

공개본과 등록본 중 어느 청구항을 읽어야 하는지도 표시한다. 이 목록을 받으면 팀원2가 독립항별 구성, 반복되는 기능, 회피·확보 검토가 필요한 기술 영역을 정리할 수 있다. 법률적 침해·FTO 결론을 대신 내리지는 않는다.

### 4. S커브는 적합성이 있을 때 수행

Logistic/Gompertz 적합을 계획하되, 누적 데이터 길이·변곡점 관찰 가능성·파라미터 안정성을 먼저 확인한다. 필요하면 시계열 후반부를 검증 구간으로 분리하고 모형 간 결과와 종료연도 변경에 대한 민감도를 비교한다. 누적 곡선의 높은 적합도 하나로 성숙기를 확정하지 않는다. 포화 수준이 식별되지 않으면 ‘현재 데이터로 단계 판정 불안정’이라는 결론도 유효하다. 종료연도를 2021년으로 고정할 근거는 아직 확정되지 않았다.

### 5. 협력 후보·결과팀 연결

냉각장비·냉각액 기업의 후보 5곳을 목표로 동일 데이터의 규모·성장·영향력과 사업 적합성을 비교한다. 자료가 부족하면 5곳을 억지로 채우지 않는다. 인용 지표의 정의·조회시점·연령 보정 방식은 명시한다. 특허 지표와 실제 공급역량·성능·가격·권리 접근은 구별한다.

결과팀에 기술별 주요 발견, 근거, 한계, 전략상 의미를 함께 전달한다. ‘HHI 0.18 이상이면 투자’ 또는 ‘액침이 DLC보다 5배 유리’ 같은 결론을 임계값만으로 자동 생성하지 않는다. 이 기준은 기존 초안의 잠정 규칙이며 타당성·민감도 확인이 필요하다.

## 반환 패키지와 완료 기준

권장 디렉터리: `team1/raw/`, `team1/clean/`, `team1/analysis/`, `team1/figures/`, `team1/handoff/`. 개인정보·계정 정보가 포함된 export는 공개 커밋 전에 제거한다.

- [ ] 원본 데이터, 실제 검색식·검색일·필터·집계 단위가 있음.
- [ ] 정제 결과에 중복·제외·경계 사례의 이유가 남아 있음.
- [ ] 그래프별 계산표/코드와 분모가 있고 원자료와 합계가 맞음.
- [ ] **미국 핵심특허 목록과 선정 기준이 팀원2에게 반환됨.**
- [ ] S커브 결과 또는 미실시/판정 불가 이유가 있음.
- [ ] 협력 후보, 건물 연계 분석에 실제 출처와 판정 이유가 있음.
- [ ] 결과팀용 요약: 기술별 결론·한계·전략 함의가 구분됨.
- [ ] 발표용 PNG와 슬라이드별 짧은 대본이 있음. 원자료 없는 수치·빈 표를 완료 처리하지 않음.

## 발표 스타일

장표에는 핵심 그래프·표·번호·출처·해석만 넣고 상세 설명은 대본으로 분리한다. 공간을 채우는 장식성 문구·불필요한 부제는 피한다. 관찰 사실, 해석, 제안을 구별한다. 최신 연구가 기존 국내 분석의 오류를 발견하면 원본 기록을 남기고 수정 근거를 설명한다.
